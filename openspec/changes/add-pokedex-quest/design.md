Deviation from the first draft: the tab bar lives in `app/(tabs)/` (Play and Glossary as tabs) and `battle.tsx` sits
outside that group so it pushes as a modal instead of becoming a third tab. `src/theme/tokens.ts` holds the design
tokens instead of `src/shared/theme/`.

Hard rules: `logic/` is pure (no React, no axios, no store) and is what the unit tests hit. `ui/` never imports axios.
`app/` files only compose features.

## Data flow

```
BUILD TIME (once, manual)
  PokeAPI --> scripts/genSeed.ts --> src/shared/data/pokedex.gen1.json (151 entries, committed)

RUNTIME
  world + battle   -> seed only            (no network, deterministic)
  glossary list    -> seed only            (instant, offline)
  glossary detail  -> seed immediately, then axios /pokemon/{id} + /pokemon-species/{id}
                      -> cache in AsyncStorage (TTL 30 days), silently keep seed on failure
  sprites          -> expo-image, cachePolicy "memory-disk"
```

Rationale: the demo tour must never depend on hotel wifi. PokéAPI is an enhancement, not a dependency of gameplay.

## World generation

- Chunk = 20x20 tiles, generated by seeded hash of `(worldSeed, chunkX, chunkY)` — nothing stored, no boundary.
- Tile types: path, grass, tall grass, water (blocked), rock (blocked). Tall grass = 18% encounter per step.
- Persist only `worldSeed`, current chunk, tile position. Guaranteed first encounter: a `firstEncounterDone` flag.

## Battle engine

- Single pure entry point: `resolveTurn(state, action, rng) -> { state, events[] }`. Events are log lines/media cues the
  UI plays back; the UI never computes damage itself.
- Damage: Gen-1 style formula on level, attack, defense, STAB, 18-type multiplier, 6.25% crit, accuracy roll before
  damage, PP decremented per use.
- Catch rate: rises as wild HP falls (`a` scaled by HP ratio, ball multiplier for Poké Balls). Success adds to party,
  or to storage when the party holds 6; both mark the dex.
- Player actions: Use Move, Switch, Use Item, Run. Switch and non-damaging items consume the turn; Run is 80% against
  wild Pokémon.
- XP and level up use Gen-1 thresholds; level-up moves are learned automatically (no modal, keeps the tour flowing).
- Randomness always comes from `lib/rng.ts` (mulberry32, injectable seed) so unit tests replay exact battles.

## State model

One zustand root store composed of three slices: `party`, `world`, `pokedex`. `party`, `world` and `pokedex` are wrapped
by `persist` (AsyncStorage, version + migrate). **Battle state is not in the store at all** — the battle screen owns it
with a lazy `useState`, which makes "a reload never restores a half-finished battle" true by construction rather than by
a `partialize` list. Components read with narrow selectors (`useStore(s => s.world.encounterRisk)`, `useShallow` for
multi-field) so a step does not re-render the Glossary or the move grid.

## Performance rules (acceptance criteria, not decoration)

Applied precisely — only where a re-render or a layout pass would otherwise happen:

| Tool | Used for | NOT used for |
|------|----------|--------------|
| `React.memo` | `Tile`, `PokemonRow`, `MoveButton`, `TypeBadge` — repeated pure components with primitive props | components receiving inline objects/arrays, or components that always get new handlers |
| `useCallback` | handlers crossing into a memoized child (`onTilePress`, `onSelectMove`, `onSwipe`) | zustand actions (their references are already stable), handlers used only inline |
| `useMemo` | filtering 151 entries (search + type), 18x18 type chart lookup, damage preview | trivial arithmetic, JSX construction, single-field selectors |

Additional rules:

- Player movement animates with Reanimated `translateX/translateY` on the UI thread; a step must NOT re-render the
  64 tiles. Tile keys are stable: `${chunkX}:${chunkY}:${x}:${y}`.
- Glossary list uses FlatList (or FlashList) with `getItemLayout`, `initialNumToRender: 12`, `windowSize: 5`,
  `removeClippedSubviews`; sprites via `expo-image` with `cachePolicy="memory-disk"`.
- All styles created once with `StyleSheet.create` at module scope — no inline style objects inside `map()`.
- `react-hooks/exhaustive-deps` is an error and must not be silenced without a written reason.
- Every memoization has to be justified by a render-propagation path; blanket `memo`/`useMemo` is treated as a defect.

**Deviation from the draft:** a hold-to-repeat D-pad replaced the sketched analog stick. Grid movement is discrete, so a
discrete control has fewer moving parts, works with screen readers, and removes drag-versus-tap ambiguity. Reanimated
still owns the camera translation, so a step animates on the UI thread and does not re-render the 400 tiles.

## Decisions locked (from explore)

| ID | Decision | Why |
|----|----------|-----|
| D1 | expo-router, thin `app/` | tab layout + deep links for free, features stay in `src/features` |
| D2 | Grid map rendered with Views | works in Expo Go, deterministic, unit-testable |
| D3 | Bundled seed first, PokéAPI enrich + cache | battle must work offline; REST list endpoint would need 1025 requests |
| D4 | AsyncStorage + zustand persist (versioned) | MMKV needs a dev build, breaks the QR requirement |
| D5 | Full turn-based battle (4 moves, switch, items, XP) | requested by the user |
| D6 | First tall grass step always encounters, then 18% | the two-minute demo must not depend on luck |
| D7 | Expo Go compatibility is a hard requirement | reviewer scans a QR code; APK is phase 2 |
| D8 | Gen-1 only (151), English UI, persistence on | scope control |
| D9 | Status effects (burn/poison/paralyze) skipped | phase 2, keeps the engine small |
| D10 | Automatic move learning on level up | no modal interrupting the tour |
| D11 | Party overflow goes to storage, still marked caught | no dead-end when the party is full |

## Risks and mitigations

| Risk | Mitigation |
|------|-----------|
| Damage/catch balance makes the tour fail (player keeps losing) | starter at level 5, wild Pokémon level 3-5, first encounter guaranteed, catch chance tuned; covered by engine unit tests |
| Bad wifi during review | seed-driven gameplay, no network needed; detail screen degrades to seed silently |
| Persisted state corrupted by a bad migration | store version + migrate + guard: invalid state falls back to a fresh run |
| 151 sprites slow the list | expo-image disk cache + FlatList windowing as above |
| Scope creep into trainer battles / evolution | explicit non-goals above; phase 2 list in the README |

## Cost

Zero running cost: PokéAPI is free with no key, no backend, no DeepSeek/LLM usage in the app. Only local dev/build time.

### Android APK — two supported routes

| Route | Needs | Trade-off |
|-------|-------|-----------|
| **EAS cloud build** (`eas build -p android --profile preview`) | free Expo account login (or `EXPO_TOKEN`) | no local SDK, no JDK; needs network + queue; artifact downloaded as `.apk` |
| **Local Gradle** (`npx expo prebuild -p android && cd android && ./gradlew assembleRelease`) | Android SDK cmdline-tools + platform/build-tools (~3-5 GB) and JDK 17 | one-time ~20-40 min setup, then offline and repeatable; keystore generated locally and gitignored |

Recommended order: try EAS first (fastest to a real artifact, no 5 GB install), fall back to local Gradle if no Expo
login is available. Either way `android/` is generated by prebuild and gitignored, and the app stays Expo Go runnable.

### iOS IPA — what is actually possible here

| Route | Needs | Result |
|-------|-------|--------|
| EAS device/internal build | paid Apple Developer account ($99/yr) + provisioning profile | real `.ipa` installable on registered devices |
| EAS simulator build | Apple account not strictly required | `.app` for the iOS Simulator only — not an IPA you can hand to a reviewer's iPhone |
| Local `xcodebuild archive` | Xcode (~15 GB) + Apple Developer account + signing identity | real IPA, but requires installing Xcode interactively first |

Truth: a device-installable **IPA cannot be produced on this machine as it stands** — Xcode is absent and no Apple
Developer account is configured. The repo will ship `eas.json` with `development`, `simulator`, `preview` (Android APK)
and `production` profiles plus the exact commands, so the IPA becomes one command the moment credentials exist. That
gap is reported in the README rather than glossed over.
